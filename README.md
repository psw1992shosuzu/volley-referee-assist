# VOLLEY REFEREE ASSIST v2.7（STEP 28）

Androidスマートフォンでの横向き使用を想定した、6人制・9人制の非公式審判補助アプリです。得点、サービス権、サービス順、ローテーション、選手交代、タイムアウト30秒、セット間3分、コートチェンジを支援します。

**試合データは端末のブラウザ保存領域に保存されます。** サーバーやGitHubのリポジトリに自動送信・同期されません。端末・ブラウザ・URLが変わる場合は、「履歴」からJSONで保存し、移行先で復元してください。

## GitHub Pages公開手順

1. GitHubで新しいリポジトリ `volley-referee-assist` を作成します。Pagesの無料公開を使う場合は、Publicを選びます。**公開リポジトリ内のファイルは誰でも閲覧できます。** 個人情報を含む試合記録やJSONバックアップをアップロードしないでください。
2. このフォルダー内のファイルを **ZIPのままではなく展開して**、リポジトリの `main` ブランチの最上位（root）へアップロードしてコミットします。`index.html` がrootにあることを確認します。
3. リポジトリの `Settings` → `Pages` → `Build and deployment` → `Source: Deploy from a branch` → `main` → `/(root)` → `Save` を選びます。
4. `Settings` → `Pages` に表示されるURLが使えるようになったら、Android Chromeで開きます。URL例：`https://psw1992shosuzu.github.io/volley-referee-assist/`（**公開前は使えません**）。
5. Chromeの右上のメニューから「アプリをインストール」または「ホーム画面に追加」を選びます。
6. ホーム画面からアプリを起動し、**一度オンラインで画面を完全に表示してから**、機内モードで起動できるか試してください。端末を横向きにし、試合表示・得点・30秒/3分タイマー・履歴復元を確認します。

## 運用上の注意

- `file://`で開いた単体HTMLと、`https://...github.io/.../`のPWAは保存領域が異なります。自動移行しません。必要に応じて旧版のJSONを保存し、新版で復元してください。
- 一度PWAとして開いた端末上の試合データを引き続き使うには、同じURL、同じアプリで更新してください。**ブラウザのサイトデータ削除、アプリ削除、端末故障**で記録が消える可能性があります。試合後にJSONバックアップを保存してください。
- 画面保持APIはAndroid Chromeや省電力設定などによって利用できない場合があります。端末の画面自動回転を有効にし、必要に応じて端末の画面消灯設定も調整してください。
- 本アプリは公式記録用紙の代替ではありません。JVA競技規則・大会特別規則と現場の記録を優先してください。
- GitHub Pagesは静的サイト配信です。この構成にはアカウント登録、端末間同期、試合記録の外部送信機能はありません。
- 今回、GitHubリポジトリ作成・Pages公開・Android実機でのインストール操作そのものは実行していません。

## v1.4：セット開始直前の最終確認

第1セット・次セットともに「最終確認画面へ進む」から、両チームのサービス順、開始サーバー、9人制のセット間選手交代を一覧で確認できます。「確定して試合開始」を押すまではセットは開始しません。詳しい検証結果は [STEP15_TEST_REPORT.md](./STEP15_TEST_REPORT.md) を参照してください。


## v1.5：副審確認モード

試合中、横向き画面の「副審確認」をタップすると、現在のサーバー、相手へサービス権が移った場合のサーバー、各チームの次回サーバー、直近3件の選手交代を参照できます。確認だけでは得点やサービス順は変わりません。検証結果は [STEP16_TEST_REPORT.md](./STEP16_TEST_REPORT.md) を参照してください。


## v1.6：記録用紙とのサーバー照合

試合中に「副審確認」を開き、「サービス順を記録用紙と照合」を展開します。予定の背番号と記録用紙・実際の選手の番号を比較して記録できます。不一致でも得点やサービス順は自動変更しません。検証記録は [STEP17_TEST_REPORT.md](./STEP17_TEST_REPORT.md) にあります。


## v1.7：直前ラリーと次のサービスの区別

「副審確認 → サービス順を記録用紙と照合」で「次に予定されるサービス」または「直前のラリー」を選択できます。直前の選手番号はアプリで得点登録時に想定したもので、実際の選手を自動認識するものではありません。照合結果は得点を変えず履歴に保存します。詳細：[STEP18_TEST_REPORT.md](./STEP18_TEST_REPORT.md)。


## v1.8：誤タップ防止

実際のタップで650ms以内に「得点」「9人制サービス失敗」「タイムアウト」「ノーカウント」を続けて押した場合、連続処理を防ぎます（初期ON）。「副審確認 → 誤タップ防止・画面保持・全画面設定」からOFFにもできます。実際の試合ではON推奨です。設定は端末のブラウザ領域に保存され、試合JSONには含まれません。詳細：[STEP19_TEST_REPORT.md](./STEP19_TEST_REPORT.md)。


## v1.9（STEP 20）：Android実機診断と長時間使用

[Android診断ページ](./diagnostics.html)で、保存状態・オフライン用キャッシュ・画面保持APIと、再起動確認用の目印を点検できます。実機チェックリストと結果コピーを追加しました。得点などの試合データは診断で変更しません。アプリ本体はページ再表示時のタイマー復帰処理と最終保存日時を強化しました。

使用開始前に重要な試合記録はJSONで退避してください。Service Workerの模擬試験は通過していますが、**Android機内モードでの実機試験は未実施**です。詳細：[STEP20_TEST_REPORT.md](./STEP20_TEST_REPORT.md)。


## v2.0（STEP 21）｜横向き実戦操作の安全性

横向きで上段の操作ボタンを拡大し、小型画面の9人制サービス順を5人＋4人の2段表示にしました。手動で左右を入れ替える前に確認し、30秒以上アプリを離れた試合画面へ戻ったときは得点とサーバーの再確認を促します。誤タップ防止は初期ONのまま、操作ロック中に拒否した入力では待機時間を消費しません。検証結果：[STEP21_TEST_REPORT.md](./STEP21_TEST_REPORT.md)。


## v2.1：試合運用チェックリスト

第1セット開始前、各セット間、試合中の「副審確認」、試合終了後の「履歴」に運用チェックを追加しました。チェックは得点やサービス順には影響しません。試合データと一緒に保存され、JSONバックアップにも含まれます。未チェックでも操作できます。[STEP22_TEST_REPORT.md](./STEP22_TEST_REPORT.md) に検証と制限事項を掲載しています。


## v2.2：操作性評価ページ（STEP23）

試合準備・履歴から独立した [操作性テスト](./trial.html) を開き、6人制・9人制各10シナリオで押し間違い・表示の見づらさ・操作の迷いを記録できます。評価データは試合データとは別に保存され、報告文コピーとJSON書き出しに対応します。実際の試合中ではなく練習用試合で使用してください。自動テストの記録は [STEP23_TEST_REPORT.md](./STEP23_TEST_REPORT.md) を参照してください。


## v2.3（STEP 24）：操作性の改善課題管理

「操作性テスト・改善課題」から、6人制／9人制の操作について問題ありと記録した項目をP0（正確性）、P1（誤タップ・操作困難）、P2（改善候補）に仮分類できます。優先度の手動修正、対応状況、課題一覧のコピー／CSV出力に対応。STEP23の評価記録を引き継ぎます。試合データは変更しません。実機評価が未入力のときは、課題0件でも無問題を意味しません。詳細：[STEP24_TEST_REPORT.md](./STEP24_TEST_REPORT.md)。


## v2.4（STEP 25）：評価データの復元と再現手順

「操作性テスト・評価データ復元（trial.html）」から、STEP23/24で保存した評価JSONを選んで取り込めます。既定は未記録項目だけの統合、明示的に全置換も可能です。読み込み前に内容・件数を確認し、誤ったJSONは拒否します。P0/P1/P2の各改善課題には再現手順と期待結果を追加しました。試合の得点・サービス順・選手登録のデータには影響しません。詳細は [STEP25_TEST_REPORT.md](./STEP25_TEST_REPORT.md) を参照してください。


## v2.5（STEP 26）：試合記録の整合性と安全なバックアップ復元

「履歴 → 記録の保存・復元 → 試合データの整合性を点検」で、現在の試合データと端末内保存の主要情報を照合できます。試合JSONの書き出し・取り込み時には、得点・サーバー・チーム登録・選手交代・セット履歴・記録形式などを事前検査します。不正なJSONは現在の試合を変更せず拒否します。JSONに30秒タイマーの情報も含め、情報がない古いバックアップは従来どおり取り込めます。

端末保存が破損している場合、警告を表示し、黙って保存内容を上書き・初期化しません。試合ロジック、操作性評価ページは変更していません。実機でのv2.5動作と機内モードでの再起動は未確認です。

[STEP26_TEST_REPORT.md](./STEP26_TEST_REPORT.md) に自動テスト結果と制限事項を記載しています。


## v2.6（STEP 27）：Androidでのバックアップ復元実機検証

練習用の試合を使い、「履歴 → STEP 27 実機復元テスト」または診断ページから復元テストを開きます。基準状態のSHA-256照合値を保存し、JSON一致・得点変更・アプリ内復元・再起動後の一致を確認します。試合データ自体は診断ページで変更しません。タイマー残り時間・undo/redoは照合対象外です。

**本番の試合中は実施しないでください。** JSON復元は現在の試合を上書きします。[Android実機手順](./STEP27_ANDROID_TEST_GUIDE.md) ／ [STEP 27検証結果](./STEP27_TEST_REPORT.md)。


## STEP 28：実戦使用前・最終評価

`release-check.html` から端末・PWA・STEP27復元テストの確認状態を読み取り、試合運用上の10項目を利用者が手動で評価できます。未確認項目や問題ありが残る場合は「保留／要修正」とし、全条件がそろった場合に限って「限定的な練習試合での試験運用に進める状態」と表示します。公式大会への適合を保証しません。評価は試合状態と別の保存キーに格納されます。
